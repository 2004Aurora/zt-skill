# 分层排错：每次只改变一层

| 现象 | 最小检查 | 不能推出的结论 / 下一步 |
|---|---|---|
| invalid yaml | 文件是否是完整配置，是否实际返回HTML/URI/编码订阅 | 不是服务器一定坏了；先做离线解析与核心 -t |
| 有141ms/238ms但网页不通 | 确认检测类型，核对业务连接日志 | 延迟只证明该探测响应，不代表UUID/TLS/业务完成 |
| Timeout | DNS、TCP端口、监听者、双层防火墙、路由 | 不直接认定IP被阻断；先获取多个层的证据 |
| TLS handshake / SSL_ERROR_SYSCALL | SNI、证书链、域名、对端端口、客户端/服务端日志 | 不能以 skip-cert-verify:true 修复；也不能只改UUID |
| 改了文件仍旧不通 | 源配置、应用导入副本、选中项、核心运行态 | 文件落盘不等于实际加载 |
| REALITY字段与普通TLS混杂 | 先确定协议栈，再逐项比对同一入站 | 普通TLS不使用公钥、Short ID、SpiderX |
| 443始终被占 | ss进程归属、systemctl管理父进程 | 杀子进程可能被拉起；先授权迁移旧服务 |
| SERVFAIL | 权威DNS、A/AAAA、DNSSEC链、CAA | 不等于唯一原因必然DNSSEC；不要乱切DNS提供商 |
| 开代理后全机掉网 | 两客户端接管、TUN/系统代理、端口、节点递归 | 无须先重装；保存状态并退回已知配置 |
| Claude通而终端/Codex不通 | 系统代理、终端代理环境、应用连接、业务响应 | 区分网络失败、认证失败、服务端错误 |
| 403、账号/订阅报错 | TLS/HTTP是否已成功，实际错误正文 | 不承诺改IP能解决账号问题 |
| 全局可用、规则异常 | 实际命中规则、选中组、Geo数据、DNS策略 | 全局会跳过分流，不能用全局结果证明规则正确 |

在本机已获准做网络测试时，可用当前实际代理端口进行最小请求：
```bash
curl --fail --max-time 20 --proxy http://127.0.0.1:7897 https://api.ipify.org
```
这是测试，不是配置生成；只在用户允许测试时执行。不要顺手把所有应用永久代理环境变量写入 shell 配置。

收证格式：时间/时区、设备、使用配置哈希、命令返回码、关键脱敏输出、改动前后、一项尚未验证的假设。若工具权限拒绝，记录具体操作，等待授权或交付独立文件，不换入口执行同一被拒操作。
